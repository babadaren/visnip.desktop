# 截图翻译：处理方式与设计边界

本文说明截图翻译有哪几种处理方式、各自的数据边界，以及引擎设计上必须遵守的原则。轻量档的具体实现见 `docs/offline-lite-tier.md`，离线资源的下载和安装见 `docs/offline-resource-manager.md`。

## 1. 处理方式

开源发布版只编译**本机离线**（CMake `VISNIP_ONLINE_TRANSLATION=OFF`），源码里没有任何翻译服务地址。其余方式只在自行构建时用 `-DVISNIP_ONLINE_TRANSLATION=ON` 开启。

| 模式 ID | 设置名称 | 数据流 | 发布版 |
| --- | --- | --- | --- |
| `offline` | 本机离线 | 截图在本机完成识别、翻译和回填 | 包含 |
| `cloud-image` | 云端翻译 | 选区图片 → 配置的图片翻译服务 → 完整译图 | 不包含 |
| `intranet` | 内网服务器 | 选区图片 → 明确配置的内网服务 → 完整译图 | 不包含 |
| `local-ocr` | 混合（联网） | 本机 OCR → 在线文字翻译 → 本机回填 | 不包含 |

本机离线分两档：

- **轻量（默认）**：C++ OCR → 本地 `llama-server`（Hy-MT2-1.8B）→ 客户端回填，资源直接从官方渠道下载。
- **精细**：Python 整图引擎，加上 Hi-SAM 笔画分割和 LaMa 背景修复。它的推理引擎（`vislate_engine`、`vislate_server`）在未开源的服务端仓库中维护。本仓库 `resources/offline/` 里只有同步过来的客户端副本，单独无法运行。0.4.1 起精细档不再提供下载，以前安装的精细资源包自带完整引擎，仍可使用。

## 2. 数据与网络边界

- **本机离线不联网**：不上传图片或文字，不发送健康检查或预连接，失败时也不会自动改用在线服务。下载离线资源是单独的、需要用户确认的操作，和翻译时的网络策略分开。
- **模式配置的容错**：未知或损坏的已存储模式按本机离线处理，不把配置错误解释为允许上传。
- **联网模式（仅自行构建时）的约束**：
  - 地址：云端和内网地址分开保存；内网地址为空时直接失败，不回退到云端。
  - 授权：切换到会上传内容的模式前，必须先确认对应的上传说明；未确认时不发送，也不预先建立连接。
  - 请求：不自动跟随 HTTP 重定向，内网请求不使用系统代理。切换处理方式会取消未完成的请求并清理连接缓存，但已经发送的数据无法撤回。
  - 令牌：云端与内网各有一个令牌，以 `Authorization: Bearer` 发送，互不混用。云端令牌只走 HTTPS（本机回环地址除外）。
- 内网模式只是"明确指定接收方"，不是网络沙箱。服务器能否访问外网、是否调用第三方，要由部署管理员配置和验证。

## 3. 引擎处理流程

各处理方式共用同一套结构化流程，可以用不同的精度和计算后端实现：

```text
图像输入与坐标系校验
  -> OCR（文字内容、位置、置信度）
  -> 布局与上下文分组（正文、标题、菜单、表格、控件）
  -> 文字笔画分割、保护区域生成
  -> 上下文翻译（稳定 ID、段落、术语及保留项）
  -> 字体样式估计、可用区域布局求解
  -> 只对成功单元抹除原文并修复背景
  -> 字形绘制、碰撞检查、像素修改范围校验
  -> 完整无损译图、逐单元状态与失败原因
```

三种区域必须解耦：

1. **语义上下文范围**：翻译时可以参考哪些段落、标题和相邻控件。
2. **原文字抹除范围**：明确属于待替换文字的像素。
3. **译文布局范围**：允许换行或扩展的控件区域，排除图标、边框和其他文字。

大范围的上下文不意味着大范围的擦除。正文按段落翻译再重新断行；按钮、菜单项和表格单元格保持各自的 ID，但共享上下文。无法可靠排版或修复的区域保留原图并报告原因，不声称恢复了被遮挡的像素。

## 4. 模型与运行环境原则

- 固定模型版本、量化方式、提示模板和下载地址，不追随可变的 latest 标签。
- 背景修复：简单背景优先用局部算法，复杂背景再用模型。
- 字体：用候选字体重新渲染来拟合原文字形。目标语言缺字时，用许可允许且视觉接近的替代字体。
- 每种计算后端（CPU、CUDA、Vulkan）都要单独验证，失败时退回 CPU 版。
- 环境变量和模型参数不是操作系统级的网络沙箱。离线行为要在隔离环境里验证。

## 5. 工作进程与资源生命周期

- 普通启动、截图和贴图不加载大模型。模型只在需要翻译时由独立子进程加载，不放进截图主进程。
- 子进程只监听回环地址的随机端口，每次启动生成新令牌。任务取消、超时、崩溃、切换模式、程序退出时，结束整个子进程树（Windows Job Object）。
- 空闲一段时间或可用内存不足时释放模型。资源统计包含主程序和所有推理子进程。
- 截图和 OCR 文本不出现在命令行或常规日志里。

## 6. 图片翻译接口（仅自行构建的联网模式）

```text
POST /v1/image-translate
请求: image_base64, source_lang, target_lang
响应: provider, source_lang, target_lang, blocks, elapsed_ms,
      translated_image_mime_type, translated_image_base64
GET /healthz
响应: status=ok, image_translation={configured, provider}
```

- `provider` 是引擎标识，不要求是某个特定供应商。
- 编码后的上传图片上限为 4 MiB，超限时先换 JPEG 再缩小。
- 不能把任意不相干的大模型接口地址当作图片翻译接口使用。

## 7. 验收要求

- **自动测试**：只访问回环地址上的测试服务，覆盖以下几类：
  - 端点隔离、配置迁移；
  - 离线时拒绝联网、空内网地址；
  - 禁止重定向、切换模式取消请求。

  这些测试不代表模型效果或完整断网验收。
- **效果验收**：用固定的真实截图集，包含多行正文、标题、按钮、表格、图标菜单、渐变或纹理背景、不同 DPI。分别记录：
  - 漏译、误译、排版失败；
  - 原文字残留、保护区域的像素变化；
  - 冷启动和热任务的耗时，所有进程的峰值资源。
- **离线安装验收**：在断网、没有开发工具、没有模型缓存的干净 Windows 上执行。

### 已知的字体测试差异

核心测试在 `QT_QPA_PLATFORM=offscreen` 下加 `QT_QPA_FONTDIR=C:/Windows/Fonts`（使用真实系统字体）时，有两项失败，原因还没有定论：可能是测试样本对字体度量的假设，也可能是算法缺陷。

- `fragmentedSingleLineBoxesRecoverFullSentence`：恢复出 4 个框，期望 2 个。
- `shortLabelDoesNotExpandAcrossNearbyArtwork`：应用了 1 个回填单元，期望保留原图。

不设置字体目录时这两项通过，但不能把无字体环境下的通过当作真实字体的质量验收。复现：

```bat
set QT_QPA_PLATFORM=offscreen
set QT_QPA_FONTDIR=C:\Windows\Fonts
build\windows-mingw-debug\visnip_core_tests.exe fragmentedSingleLineBoxesRecoverFullSentence shortLabelDoesNotExpandAcrossNearbyArtwork
```
