# 首选项内的离线资源管理（客户端 0.2.2）

## 用户流程

首选项 → 翻译 → 本机离线 → 选择基础或精细质量 → 下载并启用。
客户端先验证小型发布清单，再显示下载量、空间与隐私说明。用户确认后下载资源，执行完整 SHA-256 校验，自动安装到当前用户目录，运行真实离线翻译自检，最后才保存并启用资源目录与质量。无需打开网页或手动运行资源包。

正常截图、贴图和选择处理方式不会触发模型下载。下载需要联网；离线图像推理不会调用资源管理器，也没有在线翻译回退。

“高级：已有资源”保留给已有资源迁移和受控内网分发，正常用户无需操作。

## 边界

- 资源清单：HTTPS 固定域名 + 内置 RSA-3072 公钥验签，签名覆盖原始 payload 字节。执行前检查平台、ABI、版本、依赖、来源、大小、SHA-256 和有效期。
- Windows CNG 负责验签。不支持的平台直接拒绝，不做无签名回退。资源清单签名不等于 Windows Authenticode 签名。
- 网络响应禁止重定向，不附带浏览器 Cookie 或管理员凭据。分段流式下载支持中断续传；不在内存中缓存 GiB 级安装器。
- 下载缓存按 SHA-256 标识，重新使用前仍做完整文件校验。基础与精细共享基础安装器缓存，不重复下载同一包。
- 新资源安装到隔离的 managed 目录，不覆盖当前使用中的资源目录。安装失败或自检不通过不会切换配置。
- 安装器仅以当前用户权限运行，不请求 runas。Windows Job Object 管理安装器及其子进程，暂停或退出时结束本次进程组。
- 关闭首选项后任务随现有对话框对象继续；退出整个客户端结束任务并保留下载部分。下次点击可重试。
- 配置只在真实自检成功后改变。普通截图进程不常驻加载大模型。

## 目录

`%LOCALAPPDATA%/Visnip/offline/downloads/` 保存可续传缓存；成功资源位于相邻的 `managed/`。

缓存保留用于重试及精细模式复用，当前没有后台自动删除用户资源。磁盘空间不足会先拒绝，不清理用户已有模型或截图。

## 客户端适配器与自检

体积很小的第一方 `native_translation.py` 随客户端嵌入 Qt 资源，由 `visnip/scripts/sync_desktop_offline_adapter.py` 与引擎源码同步。它只写入新准备的非活动目录；目录身份同时包含模型包哈希和适配器哈希，避免覆盖正在使用的资源。已有同一适配器版本只检查、不改写。

这样修复翻译提示模板时不必重新下载未变的 GiB 级模型。自检必须至少识别三个区域、无未回填提示、实际产生不同的译图；返回原文不算成功。发现旧模板在三条英文测试中原样返回后，已改为明确语言全名及分开的背景/待翻译对象，保持数字与 JSON 键验证。

遇到 429/502/503/504 时丢弃错误页面，只保留正确的包字节，并从已下载位置重试。损坏的完整缓存不会触发未经再次确认的全量下载。

## 验证

`visnip_offline_resource_tests` 覆盖生产公钥签名、清单篡改/过期、下载来源限制、HTTP Range、配置页面显式授权边界及失败保留。

实际下载、安装和自检是独立验收：显式设置 `VISNIP_RESOURCE_REAL_TEST=basic` 或 `precise`，同时设置 `QTEST_FUNCTION_TIMEOUT=1800000`，再运行 `realProvisioningWhenExplicitlyRequested`。该验收会真实下载/安装资源，不能纳入默认离线单元测试。QtTest 默认的单项超时不适合 GiB 级资源下载。

2026-09-18 验证：基础包已通过真实清单验证、完整缓存哈希验证、自动安装与三段英文→中文自检（模型约 9.2 秒）。另外通过 `VISNIP_RESOURCE_PREFS_REAL_TEST=1` 的 `realPreferencesActivationWhenExplicitlyRequested`，在隔离设置文件中验证了实际首选项按钮、确认弹窗、真实模型自检以及配置自动保存。该次复用了已下载并核验的安装器，耗时不能当作完整网络下载耗时。

0.2.2 为安装器显式提供 NUL 标准输入输出，并只继承白名单句柄，避免 GUI 父进程的控制台/管道使精细资源 Python 安装助手在退出阶段等待。精细包的真实自动安装、自检已通过：三条英文全部产生译图，自检约 56.3 秒，安装加自检共约 115.5 秒。该验收从已签名清单匹配的完整缓存开始；公开网络下载测试曾被暂停，不能把它描述为本次完成了全部精细包的公开 HTTP 传输。
